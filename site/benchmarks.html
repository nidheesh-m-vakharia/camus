These benchmarks are preliminary. They were run on one laptop, with the object store on the same machine. Benchmarks over a real network, against real object storage, are coming.

What one machine measured.

Latency and throughput for a produce, memory per broker, and the costs that changed in the last round of performance work. Each table compares the newest run with an earlier one. The full output is in the Benchmarks README.

Setup

2026-11-10, commit 56f0c3a. Apple M4 Pro, macOS, APFS on the internal SSD. Release build. MinIO in Docker on the same machine. The machine was otherwise idle, and each benchmark ran once.

The baseline is 2026-11-05, commit 97cd9f3, on the same machine. All brokers share one SSD, and on macOS fsync is a full device flush. Numbers with three brokers are pessimistic for that reason.

What each one measures

  • 8 partitions in one request. One produce request carries a batch for each of 8 partitions, as a client batching for one broker does. Before is from #117.
  • Ack to a waiting consumer. A consumer long-polls at the end of the log while a producer sends one batch every 50 ms. Each of 200 samples is the time from the produce's acknowledgement to the fetch returning that batch. Before is from #122.
  • 5 produces in flight. One connection keeps five acks=all produces outstanding, as a Kafka client does by default. Before is from #123.
  • Metadata writes. 64 writers make 200 writes each to the metadata group, the way consumer groups committing offsets do. Before is from #127.
  • 3000 sealed extents. Uploads run every millisecond, so each batch becomes its own sealed extent. Then it measures the partition's metadata row, a fetch of the newest extent, a produce, and a consumer reading all 3000 batches from the start, then again from the local cache. Before is from #119 for the row and the fetch, and #125 for the full read.

Linux

Some of these were also run on Linux, in an OrbStack VM on the same Mac. Those results are in the descriptions of #118 and #120. They are useful only as before and after comparisons, so they are not in these tables.

Run them yourself

Every benchmark is an ignored test, run in release mode. The ones with CAMUS_MINIO=1 need the local bucket from the bucket page.

CAMUS_MINIO=1 cargo test --release -p camus-broker --test latency -- --ignored --nocapture
CAMUS_MINIO=1 cargo test --release -p camus-broker --test throughput -- --ignored --nocapture
CAMUS_BENCH_BROKERS=1 CAMUS_MINIO=1 cargo test --release -p camus-broker --test throughput -- --ignored --nocapture
CAMUS_MINIO=1 CAMUS_BENCH_BROKERS=1 CAMUS_BENCH_PARTITIONS=8 cargo test --release -p camus-broker --test latency -- --ignored --nocapture
CAMUS_MINIO=1 cargo test --release -p camus-broker --test extent_cost -- --ignored --nocapture
cargo test --release -p camus-broker --test tail_latency -- --ignored --nocapture
cargo test --release -p camus-broker --test pipelined_throughput -- --ignored --nocapture
cargo test --release -p camus-metadata --test write_throughput -- --ignored --nocapture
