The longer documents live in the repo.

This site is the operating guide. The repo holds the decisions and the API matrix. Those stay next to the code because they change when an API is implemented.

Plan

The plan is what has been accepted, phase by phase. A later phase's API is not given a success path early. The plan is the list of what "done" required, including the client tests.

ADRs

The ADRs are the decisions: the wire protocol and the 4.4.0 pin, Raft, durability and acknowledgements, offsets, ACLs, and how a phase is allowed to ship. When this site and an ADR disagree, the ADR is the one that was accepted with the code.

Compatibility

The compatibility doc is the 4.4.0 pin and every API. A tested-client column stays empty until kafka-clients, librdkafka, or franz-go has actually passed that call. The summary of what those clients can do is on the clients page.

Crates

The workspace is protocol, broker, raft, metadata, wal, storage, uploader, coordinator, compactor, cli, and engine-bench. camus-broker is the binary you run. The uploader, coordinator, and compactor crates are part of that process. They are not empty placeholders.

Losing a majority of a write-ahead log shard is not a test failure you retry. It is recovery, and it drops acknowledged data that was not sealed yet.
